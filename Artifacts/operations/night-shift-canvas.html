Automation Procedure

The Night Shift Canvas

When this applies Before building or scheduling any autonomous/unattended Claude workflow — a recurring brief, a scheduled digest, a Routine/cron job, or any "gather → triage → prepare → deliver" background task. Run this procedure once per workflow, before the first scheduled run, not after.
01
Output — define what must be ready

State the exact deliverable in concrete terms. A vague objective ("keep me updated") cannot be automated reliably — a precise deliverable gives every scheduled run the same clear target. Define this first; every other step follows from it.

02
Trigger — decide when it should begin

Pick the actual mechanism: a fixed recurring schedule (via create_trigger or CronCreate), a self-paced dynamic loop (ScheduleWakeup), or a one-shot future reminder (send_later). State the cadence and timezone explicitly.

03
Sources — where does information actually live?

List each source by name and confirm it's connected and authorized — check ListConnectors, don't assume. Claude cannot monitor what it cannot access; an unconnected source produces silently incomplete output.

04
Rules — write down what deserves attention

Define explicit classification criteria for four buckets. Vague rules ("use judgment") produce noisy output — write specific criteria, then refine them against what the first few real runs surface.

Escalate

Deadline today, financial impact, customer risk, blocked critical work

Review

Material change, emerging risk, conflicting information

Include

Useful context, no action needed

Ignore

Duplicates, routine notifications, low-value noise

05
Actions — what may Claude prepare unattended?

State explicitly what's in scope for unattended execution: retrieving authorized information, comparing against a prior run, classifying urgency, drafting the brief, preparing (not sending) recommended actions.

06
Approval — where must a human intervene?

State explicitly what always requires human sign-off: sending sensitive communications, committing money, changing critical records, approving consequential decisions, or acting on incomplete or conflicting evidence. This list keeps the workflow inspectable.

07
Run the system readiness check

Confirm before scheduling — if any answer is no, resolve that gap before the first run, not after a bad one.

08
Revisit when the workflow's job changes

A canvas answered correctly at setup can go stale — new sources added, rules that stop matching, or output used for something higher-stakes. Re-run the relevant steps rather than patching ad hoc.

Readiness checklist — all must be yes before scheduling
  • Is the output clearly defined in concrete terms?
  • Is the timing and timezone explicit?
  • Are all sources connected and authorized?
  • Are attention rules documented in four buckets?
  • Are permitted unattended actions clearly listed?
  • Is human approval boundary explicitly defined?
