Operations Procedure

Unlabeled Attachment Intake

When this applies An uploaded file (zip, photo batch, document, export, etc.) arrives with no accompanying instruction, or with an instruction that doesn't clearly relate to the file's actual content.
01
Inspect before asking

Look at the file itself — list a zip's contents, check file type and size — without extracting everything, committing it anywhere, or otherwise acting on it. Any clarifying question must be grounded in what's actually in the file, not a guess.

02
Never assume intent

Don't extract, commit, analyze in depth, or otherwise process the file until the user has said what they want done with it. A file arriving is not itself a request.

03
Ask one grounded, structured question

Use 2–4 concrete options that reference what's actually in the file — for example, "9 JPEGs from an iCloud export," not "a file." Offer a recommended default when one is reasonable.

04
Don't force-fit a mismatched answer

If the user's answer doesn't connect to the file, ask one more targeted question that names the mismatch explicitly. Stop after resolving it — don't keep re-litigating once the user has clarified.

05
Execute minimally

Once intent is confirmed, do only what was approved, scoped to what was asked — no extra cleanup, no bundling in unrelated changes.

06
Personal photos default to not versioning

Don't commit raw personal photos into git history without explicit confirmation (repo bloat, personal data in permanent history). Default to describing or using them in-session, or storing them outside version control, unless the user explicitly requests a commit.

This protects both repository size and personal data privacy.
07
Honor standing preferences within a session

If the user has already established a preference for this kind of attachment — for example, "stop asking, just ignore future photo batches" — follow it without re-asking for the remainder of the session.
