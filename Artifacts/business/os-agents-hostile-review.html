OS Agent Hostile Review

Read-only review of the 25 os-* agents, the two commands and the rules files. All eleven findings have since been addressed in code.

Verdict

The "draft-only behind an approval gate" claim I made is true by instruction, not by enforcement. Certain The agents cannot send anything externally, because they hold no send, shell or edit tools. But every one can write any file in the repo, including its own rules, the approval record and other agents' definitions, and no hook or permission rule stops it.

Certain All eleven findings are now addressed in code and covered by 137 tests that pass on every run, and 20 deliberate bugs planted in the gate, guard and registry were each caught. That is not proof the system is safe to give outward authority.

What held up

  • Certain No agent has Bash, Edit, Agent or any MCP tool, so direct sending and code execution are not available to a subagent.
  • Certain WebFetch is limited to 4 of 25 agents. data/ai-os/* is gitignored, so lead and client data cannot be committed.
  • Likely The defense baseline is present in all 25 files and the model tiers are sensible.

Before you promote any agent

  • Re-run the live canary in docs/ai-os/README.md in your own session. It passed in the build session on 1 October 2026 with a real os-* subagent, so the agent_type assumption held there; it needs repeating after any change to the hooks or settings.
  • Set max_spend_per_approval_eur and quiet_hours_local in limits.json, initialise the registry, record consent, and fill the price list. Until then all spend and all messages are blocked.
  • Read 20 or more drafts from the agent you want to promote, then promote one agent at a time, and only when whatever acts calls os_gate.py commit first.

Fix status for 1, 2 and 6

  • 1 Write scope: .claude/hooks/os_guard.py confines each os-* agent to its own .md paths, resolves symlinks and .., and fails closed.
  • 2 Approvals: scripts/os_approvals.py records approvals only from a real terminal, bound to the exact card text, expiring after 24 h, in a hash chain. The hook and a deny rule block every agent and session from writing the ledger.
  • 6 Evidence: .claude/hooks/os_log.py writes a log the agents cannot touch; a missing log is reported as CRITICAL, not as all clear.

Certain 26 tests pass against the real scripts, including traversal, symlink, tamper, expiry and forged-ledger cases.

Certain Verified later in the same session: a real os-seo subagent hit the hooks live (see the canary section). The deny-rule backstop in settings.json was also confirmed to work.

Fix status for 3 and 4

  • 3 Exfiltration: the four web agents are read-scoped to non-private docs and fetch only allow-listed https hosts (no IPs, ports, credentials, long query or encoded chunks). Every other agent has no network tool, and a test fails if that is ever broken. os-* agents cannot call connectors.
  • 4 Main session and injection: any connector tool that can send, change or spend asks you to confirm; read-only calls pass; OS_OUTBOUND_MODE=off at launch disables it. External text must sit in untrusted fences, and the integrity report flags instruction-like text outside them (a heuristic tripwire, not proof).

Certain 49 tests pass, including look-alike hosts, userinfo tricks, IPv6, symlink and traversal reads, and 26 real connector tool names classified.

Certain Not closed: the main session can still write any file, including these hooks, and the confirmation only helps if you read it. WebSearch queries are unrestricted. Everything relies on hooks receiving agent_type, which the live canary confirmed.

Fix status for 5 and 7

  • 5 Orchestration: agents never call agents. os-chief-of-staff now only writes a routing plan (Mode A) or assembles the Morning Page (Mode B). The new /os-route command checks the plan with scripts/os_plan_check.py (real agent names, at most 6 steps, paths confined to data/ai-os/ or docs/, no instruction-like text, never planning the approval or chief agents), runs each step as its own subagent and passes files between them. Four other agents that told themselves to hand work on were rewritten to hand over through files. A lint test fails if any agent is told to call another.
  • 7 Missing sources: docs/ai-os/ops/price-list.md now exists and os-close refuses to draft while it is empty or for an item not on it. scripts/os_registry.py keeps the consent and opt-out ledgers as salted hashes (no raw emails or phones), screens an audience outside the model, and writes data/ai-os/screened/*.md. The outreach agents work only from that file and write CONSENT CHECK NOT RUN or OPT-OUT CHECK NOT RUN if it is absent. Opt-outs always win; recording consent or removing an opt-out needs a real terminal; the registry files are write-protected for every Claude session.

Certain 78 tests pass, including hostile routing plans, tampered ledgers and phone and email normalisation. The new lint was run against the pre-fix agent files and catches the cross-agent calls that were there.

Certain The registry starts empty on purpose. Until you record consent, no outreach agent is cleared to draft to anyone. The default rule is strict: marketing needs recorded consent; legitimate interest alone does not unlock it. That rule is not legal advice; confirm it with an adviser.

Fix status for 8 and 9

  • 8 Evidence: the write guard now lets an os-* agent create a file but never overwrite it or use Edit. It refuses any existing path, including a symlink or a dangling one, and tells the agent to add -2 or -3. Approval cards go in new dated files, and the same item id with different text in two files voids that approval. Integrity reports are timestamped and never replaced, so a later OK cannot hide an earlier CRITICAL. Refused overwrites are logged and counted separately from real breach attempts.
  • 9 Limits: the numbers now live in docs/ai-os/rules/limits.json and are enforced by scripts/os_gate.py. The gate reads the action from the approved card itself, so it checks the numbers you approved. It re-checks approval, 24 h expiry, single use, the consent registry, quiet hours in the recipient's timezone, the touch cap, and the limit for that action type (spend cap, budget step, prospect batch, invoice days). Any limit that is null blocks the action. os-approval is no longer the authority and may not claim an action is within limits. When you approve in the terminal you now see the machine-read action and a gate preview.

Certain 119 tests pass, stable over three runs. I mutation-tested the gate and guard with 11 deliberate bugs (off-by-one boundaries, removed single-use, removed create-only, loosened caps); every one was caught. That exercise also exposed two real bugs I fixed: a dangling-symlink gap and an expiry check that did not fail closed at age zero.

Certain Not closed: nothing in this repo sends anything yet, so the gate protects whatever calls commit. Connector sends in the main session still rely on the confirmation prompt. max_spend_per_approval_eur and quiet_hours_local ship unset, so all spend and all messages are blocked until you choose values. Three advisory limits (stop-loss, target cost per lead, cash buffer) are judgement thresholds that no action gate can enforce.

Fix status for 10 and 11

  • 10 Connectors: by default no agent can call any connector, and the agent files no longer say they can. The command that runs an agent reads connectors and passes the result as a file. Access is an exact, per-agent, read-only opt-in in docs/ai-os/rules/connector-allowlist.json, which ships empty. Wildcards and write verbs are dropped even if listed, the four web agents can never have connectors, and a test fails if an agent's tools: line and the allow-list ever disagree. Every connector bullet in the agent files was rewritten to describe a read-only source, and a lint fails on any write verb there.
  • 11 Injection reporting: agents cannot message each other, so a suspected injection is now a new file in data/ai-os/flags/. Every os-* agent may create one there (create-only, capped at 200 files). The watchdog reads them and the integrity report counts them; a full folder is reported CRITICAL because real reports may be buried.

Certain Not closed: whether an agent actually notices an injection is still the model's judgement. The draft scan for instruction-like text outside untrusted fences is a second tripwire, not a guarantee.
