What you should know first

The "workflow, not one prompt" carousel is advice, not evidence, and one slide is missing. Slide 2 of 10 was not in the upload. The eight steps are sensible, but nothing on the slides shows the chain beats a single well-written prompt, and asking a model to critique its own output shares its blind spots, so step 07's "check for accuracy" is not verification. [Certain]

The Cal.com tool on the "open-source" slide is a different product from the one you probably mean. The calcom/cal.com repository I cloned now describes itself as Cal.diy: MIT-licensed, enterprise features (Teams, Organizations, Insights, Workflows, SSO) removed, and "strictly recommended for personal, non-production use". Businesses are pointed to the paid Cal.com. Dify is not plain open source (no multi-tenant service, no logo removal without a licence), n8n uses the Sustainable Use License, Sentry's MCP server is FSL-1.1-Apache-2.0, OpenMontage is AGPL-3.0 and Open WebUI has a branding clause. I read each licence file. [Certain]

The bug-catching plugins exist, but the install counts and star counts are the creator's. Superpowers, Context7, Security Guidance, Sentry and Code Review are all in the claude-plugins-official marketplace file I read. The "294.9k stars", "241,800 installs" and "438,525 installs" could not be checked because the GitHub API is blocked here, and the slide's "only 80%+ confident issues" setting for Code Review was not found in code. Two of them (Context7, Sentry) are already in your .mcp.json. [Certain]

"5 tools everyone will be using in 2027" is a prediction, not a finding. SERPtag was not found; Cursor, Claude and ManyChat are paid products. [Likely]

The two code videos were transcribed and run. Both 16-line numpy scripts are in scripts/ with my own checks added; they reproduce the videos' figures (attention weight for "it": animal 0.85, street 0.05; bell curve 68-95-99.7). They are teaching toys: real returns have fat tails, and real attention uses learned matrices. [Certain]

Nothing was installed and no connector was changed. The batch 104 OpenFlowKit .mcp.json entry is still unapplied (your decision). Midpage Legal Research, Sentry and Supabase connectors still need authorisation by you in a session that can run the sign-in. [Certain]

6. Copy-paste prompts and commands

After restarting Claude Code the commands exist: /claude-workflow, /bug-plugin-pick, /trending-pick, /attention-explain, /bell-curve. Prompts 1 to 6 are quoted from the carousel slides; 7 to 9 are mine.

1. Step 01 to 02: raw material, then signal (quoted from slides 3 and 4)
I'm going to give you raw information. First analyze it. Don't create the final output yet.

[PASTE NOTES, EMAILS, DATA]

Analyze this first. What matters most, what is missing, and what requires my attention?
2. Step 03: analysis into action (slide 5)
Turn your analysis into an actionable plan. Prioritize the next steps and flag anything that requires a decision.
3. Step 04: the deliverable (slide 6)
Using the approved action plan, create a concise follow-up email for the team.
4. Step 05: do not accept version one (slide 7)
Critique this output before I use it. What is unclear, missing, repetitive or potentially misleading?

Then improve it based on your critique.
5. Step 06: structure the prompt (slide 8)
Create a step-by-step plan to [TASK].
Goal: ...
Context: ...
Requirements: ...
Format: ...
Examples: ...
Constraints: ...
6. Steps 07 and 08: review, then final (slides 9 and 10)
Review this text and suggest improvements. Make it clearer, more professional and concise. Highlight what could be added, removed or rephrased.

Then: Using the refined version, create a final document/presentation/report in [format]. Make it ready to use, with clear structure and key takeaways. Also suggest next steps.
7. Choose bug-catching plugins (mine)
Use the claude-bug-plugins-5 skill. My project is [DESCRIBE] and it [does / does not] handle customer data. Recommend at most three of the five plugins, say what each sends where and what account it needs, flag Sentry as source-available, and give the install lines for me to run myself. Install nothing.
8. Check a licence before building on a tool (mine)
Use the oss-tools-part3-checked skill. I want to use [TOOL] to [PURPOSE]. My use is [internal only / hosted for customers / resold]. Read its licence, tell me whether my use is allowed, and name what would require a commercial licence.
9. Learn attention (mine)
Use the ml-attention-part21 skill. Run scripts/attention_from_scratch.py and explain query, key, value, match and mix to [AUDIENCE] using its output, then say what real models do differently.
