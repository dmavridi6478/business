Business-case build order

  1. Current-state inventoryEvery AI-client × tool pairing that has, or would need, a custom integration.
  2. Current-state costBuild + maintenance cost per pairing, summed across the N×M count above.
  3. Complexity visualizationThe mesh diagram above — the single most persuasive slide, not just the number.
  4. Target-state via MCPSame clients and tools, N+M connections, hub-and-spoke diagram.
  5. Build-vs-buy per toolDoes an official/community MCP server already exist, or does one need building?
  6. Migration sequencingCut over the highest-maintenance-cost pairing first, not the easiest.
  7. Risk / caveatsState them in the proposal — see below — not just internally.
Where the pitch overclaims
  • MCP doesn't eliminate the M servers — someone still builds and maintains one per tool.
  • Existing integrations don't migrate themselves; cutover cost has to be netted against the savings above.
  • A client on a single AI client sees little benefit — this case is strongest at N ≥ 2, M ≥ 3.
  • MCP server quality varies between official and community builds — verify before counting a tool as "buy."
