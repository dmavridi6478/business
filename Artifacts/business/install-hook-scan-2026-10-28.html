Install Hook Scan

Static scan of 12 shallow clones from batch 109 · 28 October 2026 · nothing from the clones was executed

1. Result

I found no malicious install-time behaviour in any of the 12 repositories. The risk is not in installation but in what several of them are designed to do once running. Two plugins register hooks that capture your conversations, and several documents tell you or your agent to pipe a remote script into a shell.

Method and limit: I read files with grep and a Python script run in isolated mode; no package manager, build tool or script from the clones was run. A static scan finds known patterns; it cannot prove a repository is safe, and it does not cover the remote scripts the repositories tell you to download.

3. The two findings that matter

  • Memory plugins read your sessions. The agentmemory and OpenViking Claude Code plugins register hooks on session start, every prompt, tool use and stop. They send what happened, including tool output and transcript turns, to a memory server. The defaults I saw point at localhost (agentmemory port 3111; OpenViking 127.0.0.1), but an environment variable or config can point them at a remote server. Tool output can contain secrets. Install them only on projects where that is acceptable, keep the server local, and read the hook scripts first.
  • Remote installers are the real exposure. Several READMEs and skills pipe a downloaded script into a shell. That script is not in the clone and can change after you read this. Prefer package managers, pinned releases and downloading the script to read before running.

4. Hidden text and prompt injection

I scanned all markdown, script and config files for zero-width and bidirectional characters and for injection phrases such as "ignore previous instructions". Findings: zero-width characters appear in Persian, Bengali and Malayalam translations (normal in those scripts), an emoji test table, and inside a code sample in a defensive skill. The injection phrases appear in security-defence skills and in test fixtures that exist to test detection. None was found in a skill or command file that would instruct an agent to exfiltrate data or hide actions from you.

5. Not checked

  • The remote scripts and the packages those repositories download when installed.
  • Dependencies of each project; I did not audit lockfiles.
  • Runtime behaviour. A hook script can do more at run time than its source suggests if it downloads code.
  • ai-boost and walkinglabs "awesome-harness-engineering" repositories (not cloned).
