# AI side-hustle pilot

Source: @earchoe carousel (10 dark serif/mono slides). Every slide carries the caution: AI features, pricing and access change by product, plan, region and rollout - verify official documentation before selling a workflow built on a newly released feature.

## 1. The five-question filter ("save this AI side-hustle test")

1. Is there a real person with this problem?
2. Can I demonstrate the result?
3. Can I verify the AI output?
4. Can the work be repeated?
5. Would someone pay for the outcome?

Any "no" = not ready. Score yes/no only; do not average.

## 2. Don't chase every launch

Watch for a capability that changes what a small team can do, then ask: what manual service becomes easier, faster or cheaper because of it?
**Capability -> problem -> workflow -> proof -> offer.**

Example from the series: capability = commerce workflow (product research, listing, store operations); customer = someone already doing it manually; offer = a repeatable result with a clear boundary.

## 3. Start with the work, not the tool

Before prompting write down four things: a real input, the source material, the success test, the human checkpoint (where a person must approve).

## 4. Make AI prove it can do the job

Run one real sample. Compare the AI result with a human-made version. Record where the AI fails. **Loop: SOURCE -> AI -> CHECK -> PACKAGE -> SELL.** If the workflow cannot survive one real test, it is not ready to sell.

## 5. From experiment to offer

PILOT (one customer, one problem) -> PROVE (one measurable improvement) -> SYSTEMISE (document what repeats) -> EXPAND (add automation only where useful).

## 6. Prompts (verbatim; replace every [BRACKET]; read the output before using it)

**Prompt 01** - open ChatGPT or Claude, start a new chat:
```
I want to create a paid service around [TASK] for [CUSTOMER TYPE].

Design a beginner-friendly AI-assisted workflow. Show: inputs, AI steps, tools, human review points, final deliverable, quality checks, turnaround time, and what I should never automate. Keep the offer narrow enough to test with one customer.
```

**Prompt 02** - same chat, after reviewing the first workflow:
```
Turn the workflow above into a simple paid pilot for [CUSTOMER TYPE].

Give me:
1. The exact deliverable.
2. A 3-step client process.
3. What I need from the client.
4. A quality-control checklist.
5. A short offer description.
6. Three sensible pricing structures without pretending any price is guaranteed.
```

## Limits and honest notes

- Nothing here guarantees income; pricing in Prompt 02 is a structure, not a promise.
- Do not send client data to a tool before checking its terms; keep a human on every outward message (house rule: drafts only).
- Overlap check: `ai-hustle-flywheel` is the repeat loop; this skill is the go/no-go test and offer ladder.
