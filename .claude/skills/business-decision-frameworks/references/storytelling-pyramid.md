# The Storytelling Pyramid (Minto Pyramid)

*Authored directly for this repo — the parent skill's routing table pointed here, but no source content shipped with the install. This fills that gap.*

## What it is

Associated with Barbara Minto's *The Pyramid Principle* — verify against the primary source before high-stakes use, per the parent skill's caveat. The core discipline: **lead with the answer, then support it** — the reverse of how most people naturally build an argument (evidence first, conclusion last).

## The structure

```
                 [Governing thought / recommendation]
                 (the single answer — stated first)
                            |
        +-------------------+-------------------+
        |                   |                   |
 [Supporting point 1] [Supporting point 2] [Supporting point 3]
        |                   |                   |
   [Evidence]           [Evidence]          [Evidence]
```

- **Top of the pyramid**: the single governing thought — the recommendation, verdict, or answer, stated in one sentence, first.
- **Middle layer**: 3-4 supporting points, each one a reason the governing thought is true — not a topic, a claim.
- **Bottom layer**: evidence/data backing each supporting point.

## Building it (top-down, not bottom-up)

1. **Start with the answer**, even in draft form. Write the one-sentence recommendation before assembling evidence — this forces clarity about what you're actually arguing before you have a pile of supporting material to organize around it.
2. **Group supporting points logically** — either as parallel reasons ("three reasons this is true") or as a sequential argument (situation → complication → resolution). Don't mix the two structures within one pyramid.
3. **Test each supporting point with "so what?"** — if a supporting point doesn't clearly advance the governing thought, it's evidence for something else and belongs in an appendix, not the main argument.
4. **MECE the supporting points** (Mutually Exclusive, Collectively Exhaustive) — no overlap between points, and together they should cover the full argument, not leave an obvious gap a skeptical reader would ask about.

## Applying it to a slide/exec summary

- **Slide/section headline = the governing thought for that section** — a reader skimming only headlines should follow the full argument, exactly like the deck-writing mechanics in `sales-enablement`'s deck-frameworks reference.
- **Exec summary = the top two layers of the pyramid**, compressed: state the recommendation, then the 3-4 reasons, without the underlying evidence detail (that lives in the body).
- **Body/appendix = the evidence layer**, organized to match the supporting points in order, so a reader can trace any claim back to its source.

## Common mistake

Building the pyramid bottom-up out of habit — assembling all the research and data first, then trying to derive a conclusion from it during the writing process. This produces a document that recreates the analyst's own thinking journey (chronological, mostly bottom-up) instead of the reader's fastest path to the answer. Draft the governing thought first, even provisionally, and revise it as evidence complicates it — don't leave it for last.
