# Roadmap Format Selector

*Authored directly for this repo — the parent skill's routing table pointed here, but no source content shipped with the install. This fills that gap.*

## Caveat (per the parent skill)

This is a vocabulary/trade-off checklist, not a standardized taxonomy. The six formats below are presented as distinct options, but most organizations actually run two formats of the same underlying plan for two different audiences at once (e.g. a Now/Next/Later view for the team, a Strategic view for the board) — don't present these as mutually exclusive to a user who may need more than one.

## The six formats

| Format | What it shows | Best for | Weakness |
|---|---|---|---|
| **Now/Next/Later** | Three loose buckets by rough sequencing, no fixed dates | Fast-moving product teams, avoiding false-precision date commitments | Executives/sales often want dates it deliberately doesn't provide |
| **Hybrid (theme + date)** | Themes for the far-out buckets, firm dates for the near-term one | Balancing team flexibility with stakeholder need for commitment | Requires discipline to keep far-out items as themes, not silently becoming dated commitments |
| **Strategic (outcome-based)** | Organized by strategic goal/outcome rather than feature or date | Board/exec audiences who care about direction, not delivery mechanics | Doesn't tell an individual contributor what to build next |
| **Gantt (timeline/dependency)** | Fixed dates, dependencies, often swimlanes by team | Regulated/compliance-heavy delivery, hard external deadlines, multi-team dependency tracking | Communicates false precision in genuinely uncertain product work; expensive to maintain as dates slip |
| **OKR-aligned** | Initiatives grouped under the Objectives/Key Results they serve | Orgs already running OKRs, connecting roadmap directly to what's being measured | Only as good as the underlying OKRs — a weak OKR set produces a weak roadmap view |
| **Dashboard (status-tracking)** | Live status (on track/at risk/blocked) per initiative, less about future sequencing | Ongoing operational visibility, recurring stakeholder updates | Answers "how are we doing" better than "what's coming" — pair with another format for forward-looking questions |

## Choosing (or combining)

1. **Ask who's looking at it and why**, before picking a format. A roadmap answering "what should I build next" (Now/Next/Later, OKR-aligned) is a different artifact from one answering "are we on track" (Dashboard) or "where is this company headed" (Strategic).
2. **Two audiences often need two formats of the same underlying plan** — this is normal, not a maintenance failure. A common real-world pairing: Now/Next/Later internally for the team, Strategic (outcome-based) externally for the board — both derived from the same source of truth.
3. **Reach for Gantt only when dependencies/dates are genuinely fixed** (contractual deadlines, regulatory dates, hard multi-team sequencing) — using it by default for ordinary product work manufactures a false sense of certainty that erodes trust when dates inevitably slip.
4. **Reach for Dashboard when the question changes from "what's the plan" to "how's the plan going"** — these are different questions and conflating them in one artifact usually satisfies neither audience well.

## Common mistake

Picking a format because it's the one the team has always used, rather than because it answers the question this specific audience is actually asking. When a roadmap review consistently generates the same confused questions, that's usually a format mismatch, not a content problem — check whether a different format (or a second one, for a second audience) would resolve it before revising the content itself.
