# Deck Frameworks (Full Slide-by-Slide Guidance)

*Authored directly for this repo — the original `sales-enablement` skill's routing table pointed here, but no source content shipped with the install. This fills that gap.*

Expands the 11-slide framework in the main skill with per-slide content guidance, alternate structures for shorter/longer decks, and slide-writing mechanics.

## Per-slide content guidance

### 1. Current World Problem
- Open with the buyer's world as it exists today, not your product.
- State the problem in the buyer's language, pulled from discovery notes or sales-call transcripts — not marketing copy.
- One problem, stated plainly. Resist listing three problems; pick the one this buyer cares about most.

### 2. Cost of the Problem
- Quantify inaction: time lost, money spent working around it, risk carried.
- Use the buyer's own numbers when you have them from discovery ("you mentioned 12 hours/week on X").
- If no buyer-specific number exists, use a credible industry benchmark and label it as such.

### 3. The Shift Happening
- Name the external force making the status quo untenable now (regulation, competitor move, market shift, technology change).
- This slide answers "why now, not last year or next year" — the urgency slide.

### 4. Your Approach
- One sentence describing your category-defining approach, not a feature list.
- Contrast explicitly with the old way: "Instead of X, we do Y."

### 5. Product Walkthrough
- 3-4 workflows max, each mapped directly to a pain point named in slides 1-2.
- Screenshots or short embedded clips over bullet lists of features.
- Narrate outcomes ("this cuts approval time from 3 days to 20 minutes"), not clicks.

### 6. Proof Points
- Logos only if recognizable to this buyer's industry — irrelevant logos read as padding.
- Pair every metric with its source ("per G2, per our own benchmark study, per [customer] case study").

### 7. Case Study
- One story, told in full: challenge → solution → result, with a named company and a quote if available.
- Match the case study's industry/size to the prospect's when possible — relevance beats prestige.

### 8. Implementation / Timeline
- A simple week-by-week or phase-by-phase visual, not a wall of text.
- Name who does what — this slide is often what an economic buyer scrutinizes hardest.

### 9. ROI / Value
- Show the calculation, not just the output number — buyers trust math they can follow.
- State the payback period explicitly; it's often the single most-asked question after this slide.

### 10. Pricing Overview
- Show real tiers/numbers whenever your pricing model allows it. Vague "contact us for pricing" slides stall momentum.
- If enterprise pricing is genuinely custom, say what drives the variance (seats, usage, modules) rather than leaving it blank.

### 11. Next Steps / CTA
- One specific ask with a date attached ("technical deep-dive scheduled for [date]"), not "let's stay in touch."
- Name who owns the next action on each side.

## Alternate structures

| Deck length | When to use | Slides to keep |
|---|---|---|
| 5-slide flash deck | Cold intro, conference follow-up, exec skim | Problem, Approach, Proof, ROI, CTA |
| 7-slide mid deck | Second call, champion-forwarded deck | Problem, Cost, Approach, Walkthrough, Proof, Pricing, CTA |
| 11-slide full deck | Formal evaluation, committee presentation | Full framework above |
| Technical appendix | Attach, don't present live | Architecture, security, integration diagrams, API details |

## Slide-writing mechanics

- **Headline carries the point.** A reader skimming only headlines should understand the deck's argument end to end.
- **Body copy supports, never repeats, the headline.** If the body just restates the headline in longer words, cut it.
- **One visual per slide minimum.** A slide with only bullet text is a slide that should have been a one-pager instead.
- **Speaker notes carry the talk track**, not the slide itself — slides are for the room, notes are for the presenter (and for reuse by other reps).
