# Demo Scripts & Full Talk Track Templates

*Authored directly for this repo — the original `sales-enablement` skill's routing table pointed here, but no source content shipped with the install. This fills that gap.*

Full scene-by-scene templates for each talk track type named in the main skill, with timing and interaction points.

## Discovery call (30 min)

| Time | Scene | Talk track goal |
|---|---|---|
| 0-3 min | Opening | Confirm agenda, set expectation this is a listening call, not a pitch |
| 3-20 min | Qualify + understand pain | Ask open questions, let them talk 70%+ of the time; probe for the specific trigger that made them take this call now |
| 20-25 min | Map the buying process | Who else is involved, what's the timeline, what does a decision require |
| 25-30 min | Close | Summarize what you heard back to them, propose the next step (demo) with a specific date |

**Interaction points**: "What does that cost you today?" after every pain point mentioned. "Who else feels this pain besides you?" to map stakeholders early.

## First demo (30-45 min)

| Time | Scene | Talk track goal |
|---|---|---|
| 0-2 min | Opening | Restate the goals confirmed on the discovery call — confirm nothing's changed |
| 2-5 min | Discovery recap | Play back the pain points in their language, get a "yes, that's right" before moving on |
| 5-25 min | Solution walkthrough | 3-4 workflows, each opened with "you mentioned [pain] — here's how this addresses it" |
| 25-30 min | Interaction | Pause after each workflow: "does this match what you pictured?" — don't wait until the end to find out it doesn't |
| 30-40 min | Close | Summarize the fit, propose next step by name (technical deep-dive, exec overview, proposal) |
| 40-45 min | Buffer | Reserved for questions that ran long — don't cut discovery short to protect this |

**Interaction points**: ask a question after every workflow, not just at the end. A demo where the prospect never speaks is a demo that isn't landing.

## Technical deep-dive (45-60 min)

| Time | Scene | Talk track goal |
|---|---|---|
| 0-5 min | Opening | Confirm who's in the room and what they specifically need answered (security? architecture? API?) |
| 5-15 min | Architecture overview | High-level system design — enough for a technical buyer to place it in their stack mentally |
| 15-35 min | Deep dive on named concerns | Go exactly where the technical buyer's questions point — don't run a generic script if they came with specific asks |
| 35-50 min | Integration/API walkthrough | Concrete, ideally live — show the actual API docs or a sandbox, not slides describing them |
| 50-60 min | Open Q&A | Leave real time; technical buyers often hold their hardest questions for the end |

**Interaction points**: invite questions throughout rather than batching to the end — technical buyers disengage if forced to wait.

## Executive overview (20-30 min)

| Time | Scene | Talk track goal |
|---|---|---|
| 0-3 min | Opening | State the business outcome in one sentence before anything else |
| 3-10 min | Business outcomes | 2-3 outcomes tied to metrics this executive already tracks (revenue, cost, risk) |
| 10-18 min | Strategic alignment | Connect the initiative to something already on their roadmap/priorities, not a standalone pitch |
| 18-25 min | ROI | Payback period and 3-year value, shown as a calculation they can follow |
| 25-30 min | Close | One clear ask with a decision timeline — executives respond to specificity, not open-ended "let us know" |

**Interaction points**: executives often interrupt to redirect — treat that as useful signal about what they actually care about, and follow it rather than steering back to the script.

## General principles across all four

- **Demo after discovery, not before.** Guessing which features matter without knowing their pain wastes the call.
- **Customize the data/examples shown** to their industry or use case whenever possible — generic sample data reads as a canned pitch.
- **Never present to a silent room without checking in.** If nobody's spoken in 10 minutes, stop and ask a direct question.
