# Batch 119 prompts (plain text, copy and paste)

Sources: the Ankit Sharma landing-page graphic, the Charlie Hills install list and the Natan Mohart storytelling graphic. The graphics contain no verbatim prompts, so every prompt below is original and built from their content.

## 1. Landing page audit (AI search)

Audit this page against the 14-element AI-SEO landing page anatomy: question H1, named byline with credentials, outcome subheadline, question subheadings, a 40 to 60 word answer block above the fold, a crawlable build (raw HTML, alt text, transcript), problem block, FAQ block, solution block, schema, proof block with checkable numbers, comparison table, one plain-words CTA, and a real last-updated date. Page: [URL or pasted HTML]. For each element say present, partial or missing and quote the evidence. List anything that would be deceptive to publish (invented author, unpermitted logos, unsourced numbers, fake freshness). Give the three highest-impact fixes with example copy and a before and after test on five target questions. Do not promise citations.

## 2. Write the answer block

Write a 40 to 60 word answer to this question for a landing page: "[question the buyer would type]". Use only these facts: [facts]. Start with the direct answer, not a preamble. Give three variants, count the words of each, and tell me which claim needs a source before I publish it.

## 3. FAQ from real questions

Here are real customer questions from sales calls and support tickets: [paste]. Group them, pick the ten most common, and write a clean two to four sentence answer for each using only the facts I give: [facts]. Mark any answer you cannot support with [NEEDS SOURCE]. Then draft FAQ JSON-LD that matches the visible text exactly, and remind me that Google shows FAQ rich results only for some site types.

## 4. Pick the install shortlist

Here is a list of Claude add-ons someone told me to install: [paste list]. I do these jobs: [list]. Choose at most five that fit my jobs, one per job, and say which overlap (memory, token savers, workflow frameworks). For each, tell me what permissions or hooks it adds, what to check in the README and licence, how to test it on a throwaway branch, and how I will know it helped (a number). Tell me which ones to skip and why.

## 5. Story check (seven principles)

Audit this story against the seven principles: start with tension, make it human, speak in images, make it about them, show the stakes, close the loop, leave a decision. Story: [paste]. Audience: [who]. Point: [one sentence]. Score each from 0 to 2 with a quoted line as evidence. Rewrite the two weakest parts using only my facts, mark gaps as [ADD: what is needed], and flag anything that overstates, invents a scene or uses fear to push a decision. Slash command: `/story-check`.

## 6. Tell the story

Turn this point and these true facts into a story: point [..], audience [..], facts [..]. Open with tension, include one honest moment of doubt or error, one visual scene, the cost of doing nothing, what changed, a return to the opening line, and end with one decision for the reader. Give a 150-word and a 400-word version. Insert [ADD: ...] wherever a fact is missing. Slash command: `/tell-story`.
